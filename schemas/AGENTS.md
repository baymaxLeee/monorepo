# Cross-service and cross-stack contracts

This directory owns wire contracts between backend services and between backend
and frontend: generated OpenAPI artifacts, hand-authored Proto/events, streamed
protocol decisions, Desktop capabilities and their generators. Shared
implementations belong in declared libraries; services never share source.

## Contract rules

- `openapi/*.json` is generated by the producing service. Never hand-edit it or
  generated clients; change the producer and run root `just sync`.
- Proto is hand-authored source managed by Buf. Edit versioned packages, run lint
  and breaking checks, then regenerate bindings. Consumers keep generated
  adapters at their owning infrastructure boundary unless a proven shared package
  has multiple consumers.
- New event contracts use versioned filenames under `events/` and are linked from
  the owning service specification.
- Preserve compatibility: REST cannot silently break an existing version; Proto
  package and event filename versions make breaking evolution explicit.

## Streaming UIMessage contract

Before adding a Chat custom `data-*` part or SSE/`onData` field, read
[`streaming/chat-uimessage-stream.md`](streaming/chat-uimessage-stream.md).

- Prefer official AI SDK `text`, `reasoning`, `tool-*`, `file`, `source-*` and
  message metadata parts. A custom part duplicating an official primitive is a bug.
- Register every custom part in the streamed contract and runtime schema under
  `streaming/chat-ui.ts`; regenerate both consumers with `just sync`.
- Do not copy native AI SDK types or introduce a parallel client merge protocol.

## Verification

For REST changes, regenerate with `just sync` and verify producer plus consumers.
For Proto, run Buf lint/breaking checks and affected server/client tests. For
events and streams, verify schema validation, producer mapping, consumer behavior
and failure/unknown-version handling. `just sync-check` must reject drift.
