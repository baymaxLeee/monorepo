# Desktop contracts

`bridge.ts` defines the versioned, capability-only preload interface. `just sync`
generates the Electron and `@repo/runtime/desktop` consumers. Chat consumes these
capabilities from Electron's new-conversation editor, project groups in the shared Chat sidebar,
and the local-thread controller. The editor selects local/cloud execution and a natively
granted project. The sidebar groups local threads by workspace and links to the
shared Chat session surface. Page code never receives Node, IPC channels, arbitrary HTTP access, a provider secret or an
MCP endpoint/header/grant, or an arbitrary directory grant. The renderer can reuse projects from trusted local
thread history. Adding a project invokes native directory selection and records a
one-shot grant; local thread creation consumes that selected grant and never opens
the directory picker as a side effect of sending.

The native plugin picker installs a user-selected package into the authenticated scope. Listing and import return only a plugin ID and display name. Local thread creation marks personal activations with `origin: "local"`. Only platform activations cross the inference relay's plugin resolver.

Messages and chunks use official AI SDK `UIMessage` / `UIMessageChunk`. Bridge v8
accepts bounded text and inline image parts. For ordinary attachments the renderer passes
a selected `File` to `referenceFile`. The host returns a workspace-relative path for a
project file, or stores the selected bytes under a thread-private directory and returns
its read-only path. The journal records the path. Removing the thread deletes its copies.
Main and utility-process admission validate incoming payloads.
The native transport does not use cloud conversation APIs. It adds the registered transient
`data-model-retry`, `data-context-compaction` and `data-context-usage` parts for current-Turn runtime status; the parts never enter message history or model context. A stream segment starts from its original
messages. Attachment subscribes before an atomic snapshot, replays native chunks,
and deduplicates subsequent segment/index envelopes. A null chunk ends only the
subscription. Stop is a separate command. Reload never re-executes tools; after
process loss the SQLite journal marks incomplete work interrupted.

If the Electron utility process exits unexpectedly, the trusted host starts one
replacement, reopens the same scoped journal, and emits `runtime-ready` after
recovery. The interrupted IPC call is rejected and is never replayed; consumers
reload authoritative thread state before accepting another action. A replacement
that also exits fails closed and requires an application restart.

`inference.ts` is the authoritative runtime validator for the separate
LanguageModelV4 inference relay. Desktop and Chat compile identical generated
validators. The native endpoints are IAM-scoped Chat `/local-inference/config`,
`/local-inference/plugins/resolve` and `/local-inference/stream`. Plugin resolve
accepts only activation IDs/bindings and returns a trusted Turn snapshot to the
utility process through Electron main; it never crosses preload. The stream is
NDJSON of official AI SDK provider parts; it is **not** a UIMessage stream. The
relay establishes the response with one synthetic `stream-start` before waiting
for provider headers, suppresses any duplicate provider start, and emits `ping`
about every 15 seconds while provider progress is silent. Local ToolLoopAgent
converts this provider stream into the native UIMessage stream.
Provider and MCP credentials remain outside the renderer.

Input allows native text/reasoning, inline files, function tool definitions,
function tool results and bounded generation options. It rejects arbitrary
provider options, remote file URLs, hosted tools and remote response references.
Output strips provider metadata, raw chunks and unrestricted diagnostic errors. Cancellation
aborts the upstream request, including provider startup and late streams. Public gateway calls use
a 60-second default; this stream has no total-duration timeout and retains the provider's
operation-specific 120-second response-header limit. The relay maps only bounded transient reasons (`dns`, `timeout`,
`connection_reset`, `incomplete_stream`, `provider_unavailable`) to a retryable error. The local
ToolLoopAgent may restart that current model sample at most three times with bounded exponential
backoff; each attempt has a fresh request ID and accounting reservation. Partial output from the
failed sample is discarded before resampling. Completed model steps, tool calls and side effects are
never replayed. Protocol errors and non-transient HTTP failures fail immediately. The relay stores
only request ID, scope, model, token reservation/charge and deadline.

REST descriptions are generated by Chat's OpenAPI exporter; the native provider
and UI stream part types remain SDK-owned rather than copied into OpenAPI.
