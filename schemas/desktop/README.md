# Desktop contracts

`bridge.ts` defines the versioned, capability-only preload interface. `just sync`
generates the Electron and `@repo/runtime/desktop` consumers. Page code never
receives Node, IPC channels, arbitrary HTTP access, a provider secret or an
arbitrary directory grant. Native directory selection creates the local thread.

Messages and chunks are official AI SDK `UIMessage` / `UIMessageChunk`. Local
Chat uses `useChat` with an IPC `ChatTransport`; it does not use cloud conversation
APIs or add custom `data-*` parts. A stream segment starts from its original
messages. Attachment subscribes before an atomic snapshot, replays native chunks,
and deduplicates subsequent segment/index envelopes. A null chunk ends only the
subscription. Stop is a separate command. Reload never re-executes tools; after
process loss the SQLite journal marks incomplete work interrupted.

If the Electron utility process exits unexpectedly, the trusted host starts one
replacement, reopens the same scoped journal, and emits `runtime-ready` after
recovery. The interrupted IPC call is rejected and is never replayed; consumers
reload authoritative thread state before accepting another action. A replacement
that also exits fails closed and requires an application restart.

`inference.ts` is the authoritative runtime validator for the separate
LanguageModelV4 inference relay. Desktop and Chat compile identical generated
validators. The only endpoints are IAM-scoped Chat `/local-inference/config`
and `/local-inference/stream`. The latter is NDJSON of official AI SDK provider
parts; it is **not** a UIMessage stream. Local ToolLoopAgent converts this provider
stream into the native UIMessage stream. Provider credentials remain in Chat.

Input allows native text/reasoning, inline files, function tool definitions,
function tool results and bounded generation options. It rejects arbitrary
provider options, remote file URLs, hosted tools and remote response references.
Output strips provider metadata, raw chunks and diagnostic errors. Cancellation
aborts the upstream request; failures are not automatically retried. The relay
stores only request ID, scope, model, token reservation/charge and deadline.

REST descriptions are generated by Chat's OpenAPI exporter; the native provider
and UI stream part types remain SDK-owned rather than copied into OpenAPI.
