# Knowledge service

Knowledge owns user-scoped semantic documents: immutable-source conversion,
editable semantic projections, indexing, retrieval and generated-media document
lifecycle. Runtime consumes agent-facing capabilities through authenticated
platform MCP/HTTP boundaries. Follow the
[file and Asset decision](../../../../docs/ADR/files-and-assets.md).

## Ownership boundaries

- Knowledge owns `documents`, semantic chunks/indexes, staged-media publication
  state and durable Storage Claim intents. Its PostgreSQL database is `knowledge`.
- Chat owns product conversations; Runtime owns Sessions, messages, Plans and
  mutable run workspaces. Knowledge provides retrieval, not Agent execution or
  answer generation.
- Storage owns source/generated bytes, immutable revisions, physical retention,
  signed delivery and GC. Knowledge stores only `asset_id` plus immutable
  `revision_id`, never filesystem paths, buckets, object keys or raw source bytes.
- IAM/Gateway own identity verification. Admin owns embedding and rerank provider
  configuration.

## Invariants

- Ordinary code, Markdown, HTML, JSON, archives and other downloadable files
  bypass Knowledge: Sandbox authors them, Storage keeps revisions and Runtime
  registers Session files. `content_md` is a Knowledge semantic projection, not
  ordinary file authority.
- Source ingest converts and indexes the referenced immutable revision before
  returning. It remains idempotent and cluster-serialized; do not add a second
  workflow/worker path without a demonstrated product need.
- Re-index document changes. Deletion removes owned chunks. Changing embedding
  dimension requires a versioned schema migration and full re-index.
- The application use case owns each write transaction. Storage IO happens outside
  it; then re-read and lock current state/version before committing document and
  Claim-intent changes together. Repositories never commit independently.
- Resource owners authorize delivery before requesting a Storage capability. Do
  not locally sign URLs or proxy raw bytes.

Run `just test backend/knowledge`; verify conversion/index idempotency, Claim-intent
recovery and Storage failure paths. Run `just sync` for public contract changes.
