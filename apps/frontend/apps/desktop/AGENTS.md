# Desktop host

This is the Electron host for the existing Platform, not a second UI or Federation remote. Platform owns both Web and desktop pages. Desktop shares Web's cloud routes, history, session frame and inspectors. Its one capability-gated product surface is the Chat new-conversation editor, which may select local or cloud execution and a natively granted project. Local threads still render Chat's shared session components; do not add a local history/sidebar, workspace browser, second composer implementation or Desktop-only inspector. Web development does not launch Electron. Development loads an explicit Platform URL; release packaging embeds the production Platform and MFE outputs behind the privileged `app://platform` origin and proxies only same-origin `/api/*` requests to the pinned gateway. Native capabilities are exposed only to that selected renderer origin and main frame, with no Node or arbitrary HTTP/file capability.

`electron/` owns trusted main/preload and the Agent utility process hosting the shared harness; `native/` owns the macOS command supervisor. Browser UI belongs to the Chat MFE. Validate every IPC sender and payload. Only native directory selection grants a workspace. Inference uses IAM and the Chat relay; no provider secret, cloud conversation or Storage upload belongs here. Keep credentials out of tools.

`@repo/agent-runtime` is the single RuntimeTurn/context kernel for Runtime server and this local host. Do not define a second ToolLoopAgent, input queue, context projection, prepareStep policy, prompt assembler, tool envelope or approval policy here. `electron/runtime/` owns only the SQLite journal, workspace, relay and sandbox adapters. Shared Bash manifests emit the same native terminal metadata and ToolOutcome as cloud tools. Native UIMessage parts own the Agent protocol. Persist local history atomically outside workspaces. Shell and file helpers use Seatbelt; never fall back to unrestricted execution. Cleanup includes detached descendants and parent death. Linux/Windows refuse local execution.

Use root `just build desktop`, `just test frontend/desktop`, `just desktop-dev` and `just desktop-package`. Native integration tests require macOS. Development builds do not prove signing/notarization or production model connectivity.
