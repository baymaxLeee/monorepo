# 变更闭环

用于行为修复、契约或配置变更，以及涉及状态、权限、并发和资源生命周期的实现。
这是根 `AGENTS.md` 的执行补充。只检查本次触发的项目，不要求额外报告或全量重测。

## 修改前定位

从真实入口追踪到实现和消费者，找到已有测试与最近的同类实现。
以代码、Schema、配置和已确认的需求判断行为，不只依赖聊天记忆或名称猜测。
若实现与预期冲突，先确认需要保护的契约；不要直接把文档改成错误实现的描述。

确定本次可观察的结果、一个可能出现的错误实现，以及能区分两者的检查。
修复缺陷先运行能复现缺陷的测试；新增行为优先先写行为断言，再实现。
测试失败必须来自目标行为，缺依赖、导入失败或测试未被发现不算复现成功。

## 按触发条件同步

| 触发条件 | 同步与验证 |
| --- | --- |
| API、事件或跨服务消息变化 | 从 `schemas/AGENTS.md` 定位事实源；追踪生产者、传输映射、消费者和错误分支。适用代码生成时运行 `just sync`，验证双方行为和生成差异，禁止手改生成文件。 |
| 服务、端口、路由或服务绑定变化 | 从 `services.yaml` 追踪相关 just recipe、`Procfile.dev`、配置样例与部署入口。运行 `uv run --project apps/backend python scripts/check-services.py`，并按基础设施路由验证受影响启动或部署路径。该脚本不能证明任意业务配置字段已同步。 |
| 普通配置字段或默认值变化 | 搜索字段名、环境变量名及读取点，核对解析器、样例、部署注入、启动校验与文档；测试缺省值和无效值。新增字段不能只在本地配置中生效。 |
| UI、设计系统或 overlay 变化 | 遵循前端路由，运行相关测试和 `pnpm lint:ui-contracts`；该检查不替代类型检查、交互测试或确有必要的渲染验证。 |
| SDK 或共享库 API 变化 | 检索实际调用者，核对安装版本的签名与语义；运行受影响消费者的类型检查、测试和构建，不能仅验证库本身。 |
| 状态、权限、租约、重试或资源持有关系变化 | 明确允许与禁止的转换；覆盖相关的跨 scope 拒绝、重复执行、取消、失败、回滚、替换或清理路径。仅测试成功响应不足以证明生命周期正确。 |

表中命令是针对性检查，不替代根 `AGENTS.md` 与最近目录要求的完成门禁。
`just sync-check` 会重新生成并与 Git 比较；未提交的预期契约变化也会产生差异。
须检查差异内容，不能为了让命令变绿而丢弃用户修改或自动提交。

所有代码修改完成后执行根 `just test-affected`（默认比较 HEAD，包含暂存、未暂存与未跟踪文件），
或明确执行 `just test <target>`；用 `just test-list` 定位目标。
比较分支时显式传入分叉基线；`just test-affected <base> all --list` 可预览选择。
全仓测试工具变更执行 `just test`。测试政策见 ADR-0075。

## 完成时核对

- 检查本任务的最终差异，包括新增文件；确认消费者和失败路径没有遗漏。
- 检查断言是否能拒绝目标错误实现，不能只断言 mock 被调用或照抄实现公式。
- 保留仍有效的通过结果；后续修改只重跑受影响的检查。
- 如发现重复故障，优先扩展现有门禁，并用一个会被拒绝的错误样例验证门禁。
- 仅在长期约束变化时更新其权威文档，说明原因、禁止路径和必要恢复条件。
- 在对话中简述修改、实际执行的检查与未验证项，不创建独立验收文档。
